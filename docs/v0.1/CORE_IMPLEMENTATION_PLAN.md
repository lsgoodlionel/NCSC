# 核心实施计划

## 最小范围

领域建议：“软件项目状态与资源约束”。它可覆盖时间、否定、因果陈述、口径冲突，又不涉及高风险自动决策。

- 40–80 个概念版本、10–20 个关系、5–10 条严格规则。
- 150–300 条中文人工金标，含事实、否定、未知/缺省、时间、单位、歧义、冲突、因果陈述。
- Python 3.12 模块化单体；Pydantic/dataclass + JSON Schema；SQLite 仓储接口。
- 不做开放域本体、自动概念创建、训练、外部行动、微服务或图数据库运维。

## 6–8 周

1. 冻结 IR 0.1、标注指南、词表和 30 条对抗例；两人试标并记录分歧。
2. 实现注册表、规范序列化、引用/角色/时间/来源验证（无模型）。
3. 实现查询、有限规则、四值结果、轨迹和冲突候选分类。
4. 三个解析入口：人工 IR、规则解析器、一个可替换模型适配器。
5. 建立普通 JSON、简单属性图/三元组、有限规则三条基线。
6. 执行消融：完整、无模型、替换模型、移除迁移、移除时间/来源。
7. 误差分析与 Go/No-go；不为通过测试删除失败样例。

## 可复现数据

先哈希去重，再按情景/模板族/实体族分组划分，避免近重复泄漏。固定 train/dev/test 清单、随机种子和测试集；另设组合泛化、时间、否定挑战集。组合泛化结果对划分很敏感，应分别报告（[语义解析组合泛化评估](https://aclanthology.org/2020.findings-emnlp.225/)）。每次记录代码、Schema/词表/规则、模型/提示、数据哈希、环境和原始输出版本。

## 指标

- 节点/边/角色 F1、概念规范化准确率、图 exact match。
- 否定、时间、量值单位、模态、认识状态分项准确率。
- 非法结构召回/误报、引用完整性。
- 推论 precision/recall、轨迹正确率、过度推论率。
- 冲突候选 F1 和冲突类型准确率。
- evidence/source/time 完整率及正确率。
- 同义改写、模型/解析器替换后的规范图一致率。
- 延迟、存储、规则规模曲线。

建议门槛：无模型校验测试 100%；窄域过度推论率 ≤2%；否定/时间/来源各 ≥95%；重复运行完全相同；模型替换后存量知识零迁移。解析门槛待试标后设定。

## 基线和归因

同数据、同模型、同提示预算比较：自由文本；普通 JSON Schema；简单 KG；逻辑/规则；NCSC；无模型 NCSC。只有 NCSC 相对 JSON/KG/逻辑在预注册指标稳定改善，才能归因于其特有设计，否则保留更简单方案。

结论：建议用一次窄域预算启动。两轮后若只增加复杂度而无错误率、溯源或迁移优势，应停止扩张，保留 Schema/测试资产。
