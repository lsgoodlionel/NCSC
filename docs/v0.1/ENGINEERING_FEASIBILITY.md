# 工程可行性

## 判定

| 内容 | 判断 | 边界 |
|---|---|---|
| 稳定 ID、版本、别名、迁移 | 可现成实现 | 稳定不等于永不纠错 |
| 命题、事件、证据、双时间、来源 | 可现成实现 | 可借鉴图/关系模型与标准词汇 |
| 类型/角色/基数校验、有限规则、查询 | 可现成实现 | 开放世界、例外策略需显式 |
| 中文到 IR | 需工程验证 | 窄域可做；开放域消歧仍需概率模型/人工 |
| 矛盾检测 | 需工程验证 | 先报候选，须排除时间/口径/来源差异 |
| 跨模型核心语义一致性 | 需实验 | 收益可能来自 Schema 而非数字 ID |
| 十类完备性、无损语言表示 | 研究假设 | 无完备性证明，语用/文化语境难穷尽 |
| 原生表示优于 Token/KG/JSON | 研究假设 | 必须同数据同预算比较 |
| 独立通用认知 | 长期研究 | V0.1 不得声称完成 |

## 十类的反例与多轴方案

- “会议”既是事件/过程（3），又有时间（6）和参与实体（1）。
- “红色”是属性值（4），被讨论时又是概念对象（1）。
- “北京”是实体（1），作为位置值时参与空间轴（5）；角色不等于本体类型。
- “三次”同时涉及数量（7）和频率/时间（6）。
- “禁止进入”含动作（3）、否定/义务模态和规范边界（9）；9 过宽。
- “若下雨则取消”是条件结构（8），其中仍有两个事件。
- 未知、缺省、未定义、空集合、SQL NULL 的推理行为不同，不能压成 0。

建议十类只作 `coarse_tags[]`，另设正交轴：`ontological_kind`（entity/event/state/quality/relation/proposition）、`role`、`value_kind`（identifier/quantity/text/time/reference）、`epistemic_status`、`polarity`、`modality`、`temporal_extent`、`provenance`。对象可多标签，角色由边表达。

## 必须固定的语义边界

- 未知：没有足够支持，不推出真或假。缺省：字段未给，不等于事实未知。
- 否定：命题的显式负极性，不等于查无记录。
- 矛盾：两个适用范围重叠的命题不可同时成立；先核对实体、时间、口径、上下文和来源。
- 时间：至少分有效时间、记录/获知时间、事件时间、断言时间。
- 溯源：谁/什么系统何时依据何证据生成或转换了哪一版本对象。
- 不确定性：置信度带方法和校准语境；模型分数不是事实概率。
- 因果：`reported_cause` 与 `validated_causal_claim` 分离；“因为”只产生前者。

## 成熟技术能证明什么

[PROV-O](https://www.w3.org/TR/prov-o/) 可表达 Entity/Activity/Agent 及生成关系；[OWL-Time](https://www.w3.org/TR/owl-time/) 提供瞬时、区间、持续和排序词汇；[SHACL](https://www.w3.org/TR/shacl/) 支持图约束与验证报告；[JSON-LD 1.1](https://www.w3.org/TR/json-ld11/) 可作 JSON 交换桥梁。它们证明组件可工程实现，不证明 NCSC 的十类或认知主张。

OWL 2 不默认唯一名称假设，需显式同一/不同关系或应用策略（[OWL 2 Structural Specification](https://www.w3.org/TR/owl2-syntax/)）。字符串或编号不会天然解决概念同一性。

结论：可启动 6–8 周窄域 V0.1，但成功只意味着结构正确、可追踪、可复现、无模型规则有效且相对基线有具体增益，不意味着“证明机器理解”。
