# 本机模型与规则工作台

在仓库根目录用 Python 3.9+ 启动，浏览器访问输出的本机地址。离线程序只用 Python 标准库。端口被占用时指定另一端口。

```sh
python3 -m workbench.server --port 8765
```

打开 http://127.0.0.1:8765/ ，从内置案例开始。选择「查询」和 2026-11-20，检查“未知”和被抑制的前提。换成 19、21、22 日，分别得到支持、冲突、反对。校验程序检查概念、断言、来源与时间。优化对比程序从选定日期起连续查询四天，分别测量每次重建与跨日复用同一实例的实际时间，并逐日比较完整查询结果（包括证据）。单次小样本可能受系统调度影响。导入自有 IR JSON 时先选校验。命令行和录入示例见[业务使用手册](USAGE.zh-CN.md)。

## 与模型协作

选择 Codex CLI 需要本机可执行文件及可用登录，PATH 优先，Mac 也检测 ChatGPT.app 的内置 CLI。CLI 使用既有账户和受管设置。点击运行后，工作台先用 NCSC 计算查询，再为这一轮绑定只读的事实快照和查询参数，启动本地 Codex CLI，并注册 stdio MCP 的 query 工具。模型可调用该工具获取四值结论与证据，继续用中文解释。前端按服务端发出的事件显示真实阶段和耗时。

只有 MCP 服务实际执行查询且本轮收据与本地答案摘要一致，才能显示工具调用已核验。它证明工具返回了哪份证据，模型解释的语义仍需用户复核。续问复用本服务签发的 Codex 会话，并要求快照和查询一致。服务重启后可新建会话。模型模式可能向模型提供方发送问题、查询和来源；仅处理获准发送的材料。离线 NCSC 模式不启动模型。当前界面选择的是首版内置程序及 Codex；Claude 和网页客户端的独立连接器属于后续集成。

服务只监听本机回环地址。浏览器通过 POST /run 的换行分隔 JSON 流接收阶段、结果和错误。局域网多人服务需要另行设计身份、权限、审计和存储。应用不会自动修改输入文档。

## 工程入口

- `workbench/server.py` 负责 HTTP、输入快照和程序调度。
- `workbench/mcp_tool.py` 负责固定查询的 stdio MCP 协议及工具收据。
- `workbench/codex_bridge.py` 负责 CLI 事件和续问。
- `workbench/index.html`、`style.css` 和 `app.js` 是无构建依赖的前端。

从仓库根目录运行 `python3 -m unittest discover -s tests -p 'test_workbench*.py' -v` 可独立验证这条路径。完整的 Schema 测试需安装项目 dev 依赖。

在本机 Codex CLI 0.171.0-alpha.13 上已用公开案例实测：11 月 20 日首次查询和同一会话追加核查建议，两次均取得与内核结果匹配的工具收据。若客户端策略阻止工具调用，界面应保留内核结果并显示模型侧未核验。代码只为本轮 ncsc.query 命名工具声明只读调用；系统级策略仍由本机管理。
