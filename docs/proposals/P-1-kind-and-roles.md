# P-1 概念类别与角色约束

状态：提议 · 关联 D3 · 破坏性（IR 0.2）

## 问题

0.1 的 `kind` 是自由文本（“任务”“资源”“值”“关系”），内核不读取它。因此可以把普通概念填进 `relation` 位（D3），也可以把关系当主语，校验都会通过。

## 决策

1. `kind` 取以下 6 值之一（英文代码是契约，中文是显示名）：

   | 代码 | 显示名 | 说明 | 0.1 示例映射 |
   |---|---|---|---|
   | `entity` | 实体 | 可被指称、持续存在的对象 | 资源 → entity |
   | `event` | 事件 | 有起止的过程或活动 | 任务 → event（**需人工确认**，见迁移清单） |
   | `state` | 状态 | 持续成立的情形 | — |
   | `quality` | 性质 | 可归属于对象的属性 | — |
   | `value` | 值 | 作为断言宾语的取值 | 值 → value |
   | `relation` | 关系类型 | 只能出现在 `roles.relation` | 关系 → relation |

2. 角色约束（结构层即可检查，配合 P-2 的前缀）：
   - `roles.relation` 必须是 `r:` 关系类型；
   - `roles.subject` 与 `roles.object` 必须是 `c:` 概念，不能是关系类型。
3. `kind` 是单值本体类别。概念在断言中扮演的角色（施事、位置、时间……）由边表达，不由 `kind` 表达。
4. 十类（0–9）**不进入 IR**。它只是待检验假设，作为标注数据中的实验标签出现（#6，`docs/experiments/`），内核不读取、不校验、不推理。

## 理由

- v0.1 工程可行性给出的反例（“会议”同时是事件、有时间、有参与者；“北京”作实体与作位置值）说明：单一互斥分类无法同时表示本体类别与角色。把角色移到边上，`kind` 只承担本体类别这一根轴，6 个值足以覆盖当前领域。
- 只落地一根轴，是为了不为尚无用例的维度（value_kind、modality…）预付复杂度。需要时以增量字段加入，不破坏 0.2。
- `proposition`（命题作论元）与 `quantity`（量值）暂不纳入：0.2 没有命题实例化，量值需要单位契约（候选规则 R3 依赖此项，另提）。

## 被否决的备选

- **保留自由文本 + 仅检查 relation 位**：仍无法区分值与实体，规则的 domain/range 约束无从写起。
- **直接采用十类作为 `kind`**：违反“十类是待验证假设”的项目约束，且反例表明它不是互斥完备分类。
