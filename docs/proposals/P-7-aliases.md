# P-7 别名策略

状态：提议 · 关联 D6 · 破坏性（IR 0.2，收紧）

## 问题

0.1 只要求别名是非空字符串数组：同一概念内可以重复，可以带首尾空白，可以完全没有中文；不同概念可以共用同一别名（D6）。

## 决策

1. **概念内唯一**：同一概念的 `aliases` 不得重复。
2. **去首尾空白**：别名非空且首尾不是空白字符。内部空白允许（如“API 密钥”）。
3. **至少一个含汉字**：每个概念至少有一个别名含 CJK 统一表意文字（基本区、扩展 A、兼容区），作为中文规范名候选。其余别名可以是任何文字（“Apple”“CI”“GPU”）。
4. **跨概念同名允许**：“苹果”可以同时是水果与公司的别名。这是汉语多义的正常现象，不是错误。
5. 内核**不做**别名到 ID 的解析；别名只服务于人工阅读、标注与未来的解析器。多义消解属于解析器（模型适配层）的职责，其输出仍须是带明确 ID 的候选 IR。

## 理由

- 第 4 条修订了开发方案初稿对 D6 的判断。`docs/v0.1` 明确“语言表达可多对一或多义”；若强制全局唯一，标注者只能给其中一个概念加“苹果”，另一个被迫使用不自然的名字，数据反而失真。
- 第 3 条体现“汉语原生”的项目定位，同时不排斥外来词与缩写。
- 第 1、2 条消除无意义的差异，使别名集合可以按集合比较。

## 配套建议（不属于 0.2 校验）

将来提供 `ncsc lint`，列出跨概念同名的别名供标注复核。只报告，不报错。

## 被否决的备选

- **别名全局唯一（初稿）**：与汉语多义冲突。
- **要求所有别名都含汉字**：会拒绝“CI”“GPU”等常用说法。
- **同一 `kind` 内唯一**：“苹果”（水果）与“苹果”（公司）都是 entity，仍然冲突。
