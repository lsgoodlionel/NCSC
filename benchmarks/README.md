# IR 0.2 加载和查询测量协议（#9 草案）

在仓库根目录运行以下工程检查。程序输出一份 JSON，并在查询状态、直接证据、推导前提或重复运行结果不一致时失败。

```sh
PYTHONHASHSEED=0 python3 -m benchmarks.ir02_smoke --assertions 1000 --repeats 3
```

**固定语料。** `ir02-partitions-v1` 使用契约夹具 `example-migrated.json` 的概念及前两条正断言。每两条构成一个独立上下文，同日记录任务所需资源与该资源不可用。首个分区分别查询“任务需要资源”和“任务阻塞”，命中一条直接证据和一条 R1 推导。断言规模增长时，查询所在分区始终只有两条断言。本协议测量分区数量增长的影响。大分区、长规则链、查询其他分区、冷盘读取和进程启动均需单独测量。

**时间。** 使用同一进程和 `perf_counter_ns`。每轮从相同 UTF-8 字节解析 JSON，加载正式 `KnowledgeBase`，再依次执行两条正式 `query`。加载含解析、校验、复制、建索引与规则初始化。每条查询计时含推导和证据构造。数据生成、结果编码和摘要在计时区间之外。丢弃一次预热，保留各轮原始纳秒数和中位数。默认三轮用于检查运行器。正式比较前需固定迭代次数、机器电源和系统负载。

**内存。** 在独立的额外一轮，用 `tracemalloc` 分别测量加载和两条查询各自新增 Python 分配的峰值字节。加载从已生成的语料字节开始，查询从已加载的知识库开始。进程 RSS、内核缓存、先前长期存活的分配均不在这些峰值内。计时轮不开启内存追踪。

**可重复性。** 报告记录 Git HEAD、运行器与内核源文件的 SHA-256 合成摘要、系统和 Python 版本、架构、逻辑 CPU 数、语料字节数及 SHA-256、两个查询的参数及完整规范 JSON 结果摘要。规范编码按键排序，证据数组保持返回顺序。可另起进程以不同 `PYTHONHASHSEED` 运行，比较 `canonical_answer_sha256` 和 `corpus_sha256`。计时本身预计会波动。

**范围。** 默认只运行 10³ 条断言。10⁴、10⁵、10⁶ 是手动可选梯度，分别用 `--assertions` 指定，每次只执行一个规模。较大梯度会同时占用语料、解析对象、知识库及追踪内存，须先核定机器可用内存并逐级试跑。首次工程运行结果只验证测量流程。正式规模结论待方法冻结及相应规模实测后记录。`preview_limits.py` 另用于预览实现的资源上限实验。

## 同提交的 0.2 与 0.3 工程对照

从仓库根目录依次执行。第一项直接复用 synthetic-v0 已有金标，核对四值、有序证据摘要及受抑制的前提。0.3 保留种子原有的单日和无日期写法。规模对照则为同一批事实分别编码 0.2 单日与 0.3 起止同日的闭区间。两种编码在指定查询日应得到同一状态和前提，0.3 的原始叶子另须保留区间，派生节点只在查询日有效。

```sh
python3 -m benchmarks.seed_regression
PYTHONHASHSEED=0 python3 -m benchmarks.ir02_smoke --ir 0.2 --assertions 10000 --repeats 5
PYTHONHASHSEED=0 python3 -m benchmarks.ir02_smoke --ir 0.3 --assertions 10000 --repeats 5
```

计时和峰值沿用上面的分阶段口径。不同版本的完整输出含不同来源字段，各自按固定输入复核摘要。此处通过正式 Python API 加载；CLI 的文件大小上限独立于该 API。所有样本为公开合成数据，测量方法供开发使用。

### 完整证明与预算退出

```sh
PYTHONHASHSEED=0 python3 -m benchmarks.proof_budget --repeats 3
```

两版本均用同日断言。每组先预热一轮，再测三轮，并独立测分配峰值。6 条断言形成 3 × 3 组前提，两版本都返回 9 条完整证明。128 条断言形成 64 × 64 个候选组合，两版本都以原有 `trace_budget=10000` 退出。预算记录展开工作量，不能当作允许的证明条数。种子 0 的到达限额中位时间为 0.2 的 13.25 ms 和 0.3 的 13.11 ms，查询阶段峰值均为 2,423,421 B。这两个时间只度量拒绝路径。报告将完整答案记作 `success`，符合预期的预算退出记作 `limited`，其他异常或输出不符使程序失败。种子 1 复核了相同结论。

## IR 0.3 过期区间密度的配对实验

```sh
PYTHONHASHSEED=0 python3 -m benchmarks.expired_density --expired 0 128 1024 4096 --pairs 10 --batch 7
```

两臂固定查询日 2026-11-19，目标上下文均有相同的两条当日活跃断言，由 R1 推出一条阻塞证明。为每个规模生成同一批 2026-11-18 已结束的反向断言。每条的 ID、角色、极性、来源、区间及排列保持一致，仅将这批断言置于目标上下文或第二个上下文。两臂总量相同，0 条过期断言作为空对照。每次返回的完整结果须等于只有两条活跃断言的参考结果，包括有序证据、溯源和抑制记录。

各规模先预热两对，再按 AB、BA 交替执行偶数对。每臂每对从同一份固定 JSON 字节重新构建一次知识库，随后连续执行 7 次同一查询。保留各次构建和查询耗时，用每臂各对的查询中位数汇总分布；差值在每对内部计算。答案检查在计时段外。每臂另作一次构建和查询阶段的 tracemalloc 测量，数值表示该阶段 Python 可追踪分配的峰值增量。本轮未采集独立进程峰值 RSS，不能从 tracemalloc 推算该指标。

## M2 合入后的独立复验

从仓库根目录运行 `python3 -m benchmarks.replay_scale --assertions 1000 --repeats 3`。四个独立进程分别运行两个 IR 版本及两个哈希种子，核对固定版旧基准的完整答案摘要、两种子的语料摘要、证明成功与超限结果，并重跑原 42 问。任何核对不符即异常退出。给定输入中增加互不相干的分区不会改变目标查询，故可用历史 10,000 条时的答案作为 1,000 条时的语义对照。

在主线内核 91a1f83、Apple M2、16 GiB 上，两种 IR 各 42 问通过。种子 0 的 1,000 条构建中位数分别为 16.77 / 20.01 ms，直接查询 28.13 / 40.83 µs，推导查询 32.38 / 48.29 µs，构建的 Python 分配峰值 2,752,693 / 3,316,633 字节。每组均预热一次、计时三次。6 条同日断言的两版本均有 9 条证明；128 条同日断言时两者均按原 trace_budget=10000 退出。完整环境、计时样本与结果摘要见[本轮记录](results/m5-scale-91a1f83.json)。

这些结果覆盖固定小分区与合成证明预算。当前内核在本次复验中只运行 1,000 条规模。10,000 条历史记录对应旧内核，100,000 / 1,000,000 的正式测量、全覆盖拒绝路径诊断以及深嵌套和超长字段的治理仍需单独验收。定量比较前须确认机器电源、负载和测量方法，未设置发布阈值。
