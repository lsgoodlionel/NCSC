# 大分区数量测量 v1：工程复验

基线内核 91a1f83。试跑前锁定方法。仅在 macOS、至少 8 GiB 物理内存、memory_pressure -Q 报告的系统可用百分比 ≥25% 时启动子进程；未满足只记录前置条件失败。单次仅一个子进程，父进程用 ps 每约 50 ms 检查该子进程 RSS，预算 512 MiB，墙钟 30 s，达到任一项就终止该子进程。监控失效立即终止。采样式预算可能有短暂过冲；它不是硬内存配额。不要并发测量、运行真实项目或更改系统配置。

固定 IR 0.2 单日和 0.3 当日起止闭区间，沿用 ir02_smoke.corpus、load、QUERIES 与 digest_answer。规模顺序 100,000、1,000,000；每规模先 0.2 再 0.3。每格计划三个新进程，PYTHONHASHSEED 依次 0、1、2；同格首个受限结果即停止重试。每个进程重新生成同一语料，记录语料字节数与哈希，计时解析、校验与建库。各查询预热一次后按直接、R1 顺序执行三对，报告原始 ns 和中位数。答案须跨进程稳定并与 1k 基准摘要一致。报告 getrusage(RUSAGE_SELF).ru_maxrss 的 macOS 字节进程峰值；包含生成、解释器和索引。被停止的进程仅有最后阶段和外部采样峰值，无成功分数。未完成三次时不外推耗时。无 tracemalloc、不修改现有 CLI/证明预算；明确区分工程预算退出与内核拒绝。电源、缓存和宿主负载不锁定，结果不作为正式容量阈值。
