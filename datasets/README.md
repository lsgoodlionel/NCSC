# 数据集

关联 #6（标注与数据）和 #7（基线与评分），现由 Codex 接手开发。

## 原则

- **不放真实敏感信息**：只用合成或已确认可公开的材料。人名使用“张工”这类通用称呼，不对应真实个人。
- 每个条目都必须能追溯到来源说明；合成条目的来源说明一律以“合成：”开头。
- 期望答案按 IR 0.2 与 P-3 方案 A 书写；0.1 行为不同的查询另外给出 `ir01`。
- 数据集未冻结前，评分结果只能用于调试，不能作为对外结论。

## 目录

| 数据集 | 状态 | 内容 |
|---|---|---|
| [`synthetic-v0/`](synthetic-v0/README.md) | 种子语料；已有固定工程快照 [ai-eng-v1](freezes/ai-eng-v1/README.md) | 26 个合成条目、42 个查询，覆盖四值、报告因果、冲突、时间、上下文与无日期分区 |

## 条目格式（`items.json`）

| 字段 | 说明 |
|---|---|
| `id` | `syn-v0-NNN`，不复用 |
| `family` | 场景族，用于分组划分（见下） |
| `text` | 中文原文 |
| `assertions` | IR 0.2 断言；与 `registry.json` 的概念合起来构成完整文档 |
| `not_annotated` | 有意不标注的片段及原因（指南 §7） |
| `queries[]` | `query`、`expect`（`status`、`evidence`、`suppressed`）、`phenomena`，可选 `ir01` |
| `notes` | 标注理由 |

`expect.evidence` 中，直接证据写 `{"assertion_id": …}`，推导证据写 `{"derived_by": …, "premises": […]}`；`suppressed` 是被抑制推导的前提列表。推导 ID 由内核按 P-2 计算，数据集不写。

## 划分与防泄漏

- **按场景族分组划分**，同一族的条目只能落在同一个集合，避免近似模板同时出现在训练和测试中。
- 划分清单写成 `splits.json`（族 → 集合），随机种子固定并记录。
- 另设挑战集（时间、否定、组合泛化），单独报告结果。

种子集现有 8 个族，ai-eng-v1 将全部族绑定到同一工程开发分区。独立训练、留出与挑战分区待新增语料并在测量前声明。

## 冻结流程

1. 完成至少一轮试标与裁决（`annotation/TRIAL_PROTOCOL.md` §6）。
2. 生成 `FROZEN.json`：每个文件的 SHA-256、指南版本、IR 版本、划分清单与种子。
3. 冻结后不再修改条目。确有错误时发布新版本（`-v1`），旧版本保留，评分报告注明所用版本。

## 测试

```bash
python -m unittest tests.datasets.test_synthetic_v0 -v
```

检查条目和断言 ID、登记表引用、证据引用、四值与现象标签覆盖，以及报告因果的规则边界。安装开发依赖后还会对每个文档执行 IR 0.2 Schema 校验。执行测试使用 IR 0.2 的 `KnowledgeBase.query`，按输出顺序核对证据与被抑制前提；带有 `ir01` 的条目另外验证旧版行为。
